# 部署架构设计

## 1. 目标
定义开发、测试、预发、生产环境的部署拓扑与高可用要求。

## 2. 生产环境部署原则
- Multi-AZ 部署
- 无状态组件容器化部署
- 状态组件集群化部署

## 3. 组件部署建议
- Gateway：K8s，初始 3 Pod，支持 HPA
- Pump：K8s，初始 3 Pod，作为 RocketMQ Consumer Group
- Dispatcher：K8s，初始 3 Pod，负责二级逻辑调度派发
- Callback Service：K8s 多实例
- Notify Dispatcher：K8s 多实例
- Worker：按 `workerGroup` 独立部署
- RocketMQ：3 主 3 从
- Redis Cluster：3 主 3 从
- MySQL/TiDB：主从或分布式集群

## 3.1 部署口径说明

### 单台 4C8G 试点版

- 控制面可部署在单台 `4C8G` 服务器上
- 推荐将 `Gateway`、`Pump`、`Dispatcher`、`Callback Service`、`Notify Dispatcher`、`Compensator` 以进程或容器方式分开运行
- RocketMQ、Redis、MySQL 优先复用外部基础设施
- 若中间件与控制面同机，则应下调性能预期并加强资源隔离

### 集群生产版

- Gateway、Pump、Dispatcher、Callback Service、Notify Dispatcher、Compensator 均建议至少 `3` 实例部署
- RocketMQ 采用 `3 主 3 从`
- Redis Cluster 采用 `3 主 3 从`
- MySQL/TiDB 采用高可用或分布式部署
- Worker 按 `workerGroup` 独立扩缩容，并支持多可用区分布

## 4. 环境分层
- DEV：功能开发验证
- SIT：联调与基础测试
- UAT/PRE：预发与压测
- PROD：生产环境

## 5. 发布与回滚
- 灰度发布
- 蓝绿或滚动升级
- Worker 支持 DRAINING 优雅下线
