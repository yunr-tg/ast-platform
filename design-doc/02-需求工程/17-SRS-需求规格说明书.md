# SRS 需求规格说明书

## 1. 目标
定义集团级通用异步任务调度中台的功能需求、非功能需求和系统行为约束。

## 2. 功能需求
### 2.1 任务接入
- 系统应提供 HTTP/gRPC 提交任务接口。
- 系统应对请求进行鉴权、限流、幂等控制。
- 系统应生成唯一 `taskId` 并返回给调用方。

### 2.2 缓冲与调度
- 系统应将任务投递到缓冲队列。
- 系统应维护任务状态与调度状态。
- 系统应按 `tenantId + taskType + tag + workerGroup` 路由任务。

### 2.3 Worker 管理
- Worker 应注册自身能力与地址。
- Worker 应定时上报心跳和资源状态。
- 平台应维护统一的 Worker 状态视图。

### 2.4 执行回调
- Worker 应将执行结果回调给平台。
- 平台应根据令牌与状态裁决回调。
- 平台应在终态后异步通知业务方。

### 2.5 异常处理
- 系统应支持超时扫描。
- 系统应支持失败重试与死信。
- 系统应支持人工重试与人工补偿。

## 4. 约束条件
- 不使用 RocketMQ 5.x LiteTopic
- 平台与业务逻辑强解耦
- 任务执行语义为 At-Least-Once
