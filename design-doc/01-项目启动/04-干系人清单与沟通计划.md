# 干系人清单与沟通计划

## 1. 干系人清单
| 干系人 | 角色 | 关注点 | 沟通频率 |
| --- | --- | --- | --- |
| 集团技术管理层 | 决策者 | 价值、风险、投入、收益 | 双周 |
| 架构委员会 | 评审者 | 架构合理性、可扩展性、可靠性 | 关键节点 |
| 平台研发团队 | 执行者 | 需求清晰度、技术边界、交付排期 | 每周 |
| 测试团队 | 质量保障 | 可测试性、性能与故障场景 | 每周 |
| 运维/SRE 团队 | 运行保障 | 部署、监控、告警、故障预案 | 每周 |
| 业务接入方 | 使用方 | 接入成本、回调协议、排障效率 | 双周 |
| 安全/合规团队 | 审查方 | 认证鉴权、审计、数据安全 | 阶段性 |

## 2. 沟通机制
- 周例会：项目进度、问题、风险、需求澄清
- 双周汇报：向管理层同步进展与风险
- 阶段评审会：需求评审、架构评审、上线评审
- 专题会议：性能、压测、回调协议、安全审查

## 3. 沟通输出物
- 会议纪要
- 风险清单
- 决议记录
- 里程碑状态报告
- 变更申请单

## 4. 升级机制
出现以下情况需升级汇报：
- 里程碑延期超过 1 周
- 核心架构变更
- 基础设施资源不足
- 灰度阶段出现生产风险
