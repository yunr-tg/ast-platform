# 项目建议书

## 1. 项目名称

集团级通用异步任务调度中台建设项目

## 2. 建设背景

当前集团内电商、金融、OA、AIGC 等业务系统普遍存在各自为政的异步处理模式，使用线程池、定时任务、普通 MQ 或自建任务系统来承接任务。随着任务规模达到日千万级甚至更高，暴露出削峰能力不足、状态不可观测、异常恢复薄弱、资源调度割裂等问题。

## 3. 现状痛点

- 缺乏统一削峰能力，突发流量容易击穿下游数据库和微服务。
- 任务状态散落在各业务系统中，缺乏统一跟踪与排障视图。
- 超时、失败、重试、死信处理逻辑分散，可靠性无法保障。
- 缺乏对 Worker 容量与资源水位的统一感知，调度僵化。
- 各业务重复建设异步平台，研发与运维成本高。

## 4. 建设目标

- 建设独立、语言无关的集团级异步任务调度中台。
- 统一承接集团异步任务接入、缓冲、调度、执行、回调与补偿。
- 提供高可用、高吞吐、可观测、可运营、可追溯的基础能力。
- 支持多业务线统一接入，降低重复建设与运维成本。

## 5. 建设范围

本期纳入范围：

- 统一任务接入 Gateway
- 任务状态机与任务生命周期管理
- Scheduler 调度引擎
- Worker SDK 与 Worker 注册/心跳机制
- 业务回调通知、失败重试、死信能力
- 基础监控、告警、运营查询与人工补偿能力

本期不纳入范围：

- DAG 编排
- 复杂租户分级治理
- 任务计费结算中心
- 同步任务旁路

## 6. 预期收益

- 统一集团异步任务建设标准，减少重复建设。
- 通过削峰缓冲保护核心数据库与下游服务。
- 通过状态机与日志追踪提升排障效率。
- 通过智能路由提升 Worker 资源利用率。
- 为未来多租户治理、任务编排、SLA 分级奠定基础。

## 7. 建议立项结论

建议立项，并按“项目启动 -> 需求工程 -> 架构设计 -> 开发实施 -> 灰度上线”路径推进。
