# 开发进度记录 - 20260421

## 17. 任务取消 API 实现

### 1. 协议定义 (api-contract)
- 在 `ast-platform-api-contract` 中定义了 `CancelTaskRequest`。
- 包含 `tenantId`、`taskId` 和 `reason` 字段。

### 2. 网关逻辑实现 (task-gateway)
- 在 `TaskSubmissionController` 中增加了 `/task/cancel` 接口。
- 在 `TaskSubmissionApplicationService` 中实现了 `cancelTask` 逻辑：
    - 校验任务是否存在及租户匹配。
    - 使用 `TaskStateMachine` 校验状态机流转（`INIT`/`QUEUED`/`DISPATCHED` -> `CANCELLED`）。
    - 数据库状态原子更新（带版本号乐观锁）。
- 修复了 `TaskSubmissionControllerTest` 中的路径错误（`/tasks` -> `/task/submit`）并增加了取消测试用例。

### 3. 调度器防御实现 (task-scheduler)
- 验证了 `DispatcherApplicationService` 在派发前会检查 MySQL 中的最新状态。
- 如果状态不是 `QUEUED`（例如已变为 `CANCELLED`），调度器将直接丢弃该 Redis 任务（`commitTask`）而不会发送给 Worker。
- 增加了 `TaskCancellationIntegrationTest` 验证该防御逻辑。

### 4. 终态安全
- 验证了 `WorkerCallbackApplicationService` 会通过 `TaskStateMachine` 拒绝已处于 `CANCELLED` 状态的任务回调，确保终态不被破坏。
