# 全链路 Trace 实现

## 本次进展

- **Tracing 基础能力增强**：升级了 `ast-platform-common` 中的 `TraceContext`，支持 SLF4J MDC (Mapped Diagnostic Context)，确保 `traceId` 能够自动注入日志。
- **协议升级**：在 `SubmitTaskRequest`、`WorkerDispatchRequest` 和 `WorkerCallbackRequest` 等核心契约中补齐了 `traceId` 字段。
- **网关侧支持**：
    - 在任务提交时生成或接收 `traceId`。
    - 将 `traceId` 持久化到任务表并作为 RocketMQ 消息的一部分发送。
    - 在网关异步重发（Outbox Republish）时自动恢复 MDC 上下文。
- **调度侧支持**：
    - **Pump**：从 RocketMQ 消费任务时提取 `traceId` 并存入 Redis 逻辑队列。
    - **Dispatcher**：调度任务时自动设置 MDC，并透传给 Worker。
    - **Callback**：接收 Worker 回调时根据请求中的 `traceId` 恢复日志上下文。
    - **Retry/Notify**：在重试回灌和业务通知子系统中全程透传 `traceId`。
- **SDK 侧支持**：
    - `task-worker-sdk` 在接收派发请求后，自动设置线程池任务的 MDC，确保业务 Worker 的执行日志与调度日志关联。
    - 在执行完成后，将 `traceId` 随结果回传给调度器。
- **持久化升级**：在 MySQL 事实表（任务表、派发表、通知表）中统一新增了 `trace_id` 列。
- **验证**：完成了整仓 `mvn install` 验证，并修复了所有受影响的集成测试。

## 当前状态

- 平台已具备完整的全链路追踪能力：`Gateway (TraceId) -> RocketMQ -> Pump -> Redis -> Dispatcher -> Worker SDK -> Scheduler Callback -> Business Notify`。
- 所有的 `log.info/error` 调用现在都会自动带上 `traceId`（前提是配置了合适的 Logback Pattern）。

## 下一步建议

- **可观测性监控 (Prometheus)**：接入 Micrometer 暴露核心调度指标。
- **压测与性能调优**：在真实环境下验证 Lua 脚本在大并发下的公平性表现。
- **任务全生命周期视图**：基于持久化的 `trace_id` 实现简单的任务追踪 API 或管理页面。
