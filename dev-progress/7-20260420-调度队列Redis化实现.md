# 调度队列 Redis 化实现

## 本次进展

- 为 `task-scheduler` 引入 `spring-boot-starter-data-redis` 依赖
- 实现 `RedisDispatchQueueRepository` 以替换原有的 `LocalDispatchQueueRepository`
- 遵循 A+ 架构要求，采用 Redis List 承载 `readyQueue`，采用 Redis ZSet 承载 `retryQueue`
- 支持基于 `activeKeys` 的任务发现机制，初步实现了跨租户/任务类型的公平调度骨架
- 实现了重试任务到就绪队列的自动回灌逻辑（Redis 侧）
- 编写并运行了 `RedisDispatchQueueRepositoryTest` 单元测试，验证了入队、出队及重试迁移逻辑的正确性

## 当前状态

- 调度侧已具备 Redis 生产级队列能力
- 当前 `pollNextReadyTask` 采用随机选取 `activeKey` 的简化公平策略，后续将升级为 Lua 脚本驱动的严格轮询
- 尚未实现 `ready -> processing` 的原子迁移（LMOVE/RPOPLPUSH），这是下一步增强可靠性的关键

## 下一步建议

- 接入 RocketMQ 5 gRPC Consumer，实现真实 `Pump` 搬运逻辑
- 实现 Worker 真实派发网关，替换当前的日志打印实现
- 升级 Redis 调度逻辑，使用 Lua 脚本确保 `ready -> processing` 的原子性与严格公平性
- 引入 Testcontainers Redis 进行更高仿真度的集成测试
