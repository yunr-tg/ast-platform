# Redis 调度原子性与可靠性增强

## 本次进展

- 编写并集成了 `dispatch_task.lua` 脚本，实现了以下原子操作：
    - **公平轮询 (Fair Round-Robin)**：通过对 `activeKeys` 列表进行 `RPOPLPUSH` 旋转，确保租户/任务类型之间的调度公平性。
    - **原子迁移 (Atomic Move)**：使用 `RPOPLPUSH` 将任务从 `readyQueue` 原子迁移到 `processingQueue`，防止调度器在派发过程中崩溃导致任务静默丢失。
    - **动态活性维护**：在 Lua 脚本中自动识别并移除空的队列，维护 `activeKeys` 列表和集合。
- 升级了 `DispatchQueueRepository` 接口，新增 `commitTask` 和 `rollbackTask` 方法。
- 更新了 `RedisDispatchQueueRepository` 实现，采用 Lua 脚本进行调度，并支持任务的提交（从处理队列删除）与回滚（从处理队列移回就绪队列）。
- 更新了 `DispatcherApplicationService` 调度编排逻辑：
    - 派发成功后调用 `commitTask`。
    - 派发失败（无可用 Worker 或网络异常）时调用 `rollbackTask`。
- 完善了 `RedisDispatchQueueRepositoryTest` 单元测试，验证了 Lua 脚本调用和可靠性迁移逻辑。

## 当前状态

- 调度引擎已具备 **A+ 级可靠性**，满足“允许重复，不允许静默丢失”的核心原则。
- 实现了跨租户的公平调度能力。
- 目前 `processingQueue` 中的超时任务回收（针对调度器完全崩溃的情况）将由后续的 `Compensator` 子系统负责扫描。

## 下一步建议

- **完善 Worker SDK 结果回调**：目前 SDK 接收任务后尚未实现执行结果的主动上报（Callback）。
- **任务生命周期追踪**：在全链路透传 `traceId`，方便排查分布式环境下的调度轨迹。
- **引入 Compensator 扫描**：实现对 `processingQueue` 中长期滞留任务的自动回收逻辑。
