# 23-20260422-任务优先级字段预留扩展点实现

## 背景
根据之前的分析，完整的优先级调度（WFQ+老化方案）在当前P0阶段暂不实现，但需要在数据结构中预留扩展点，为后续P1阶段实现完整的优先级调度做准备。

## 实现内容

### 1. 新增 TaskPriority 枚举
- 位置：`ast-platform-domain/src/main/java/com/ast/platform/domain/task/TaskPriority.java`
- 定义：LOW(1), DEFAULT(5), HIGH(10), CRITICAL(20)
- 默认值：DEFAULT(5)

### 2. API 契约层更新
- `SubmitTaskRequest` 增加 `Integer priority` 字段（可为空）
- 向后兼容：未传priority时使用默认值5

### 3. Gateway 层更新
- `GatewayTask` 实体增加 `int priority` 字段
- 新增 `create()` 工厂方法，处理priority转换
- MySQL `gateway_task` 表增加 `priority int not null default 5` 列
- `JdbcGatewayTaskRepository` 更新RowMapper和SQL语句
- `TaskSubmissionApplicationService` 使用新的工厂方法
- RocketMQ消息payload增加priority字段

### 4. Scheduler 层更新
- `ReadyTaskEnvelope` 增加 `int priority` 字段
- `SchedulerTaskSnapshot` 增加 `int priority` 字段
- `RocketMqPumpConsumer` 读取priority字段（默认5）
- `PumpIngestApplicationService` 传递priority
- `WorkerCallbackApplicationService` 重试时传递priority
- `RetryApplicationService` 重试时从数据库查询priority

### 5. Domain 层更新
- `TaskAggregate` 增加 `int priority` 字段

## 技术要点

### 1. 向后兼容性
- 所有未传priority的请求使用默认值5（DEFAULT）
- 现有任务在数据库升级后自动获得默认优先级
- RocketMQ消息兼容旧版本（无priority字段时使用默认值）

### 2. 数据流
```
SubmitTaskRequest(priority) 
  → GatewayTask(priority) 
  → MySQL(priority) 
  → RocketMQ(payload含priority) 
  → ReadyTaskEnvelope(priority) 
  → Redis队列（当前仍为FIFO）
```

### 3. 重试机制
- 重试任务保持原优先级
- 通过 `schedulerTaskRepository.findByTaskId()` 查询原优先级

## 当前状态
- **数据结构**：已完成所有priority字段添加
- **数据流**：已完成从提交到调度的完整传递
- **调度算法**：**未实现**优先级调度，仍使用FIFO
- **Redis队列**：**未改造**，仍使用List（FIFO）
