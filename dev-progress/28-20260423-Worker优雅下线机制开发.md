# Worker优雅下线机制开发

## 概述

本次开发实现了Worker优雅下线机制，确保Worker在关闭时能够正确处理正在执行的任务，避免任务丢失或中断。

## 实现内容

### 1. Worker SDK端

#### WorkerSdkProperties配置扩展

新增配置项：
- `gracefulShutdownTimeoutSeconds`: 优雅下线超时时间（默认30秒）
- `drainingPollIntervalMs`: 排空检查间隔（默认1秒）
- `gracefulShutdownEnabled`: 是否启用优雅下线（默认true）

#### WorkerRuntimeManager

任务槽位管理与状态跟踪：
- `tryAcquireSlot(taskId)`: 获取任务槽位，DRAINING状态拒绝新任务
- `releaseSlot(taskId)`: 释放槽位，触发排空完成检查
- `startDraining()`: 进入DRAINING状态
- `awaitDrainCompletion()`: 等待所有活跃任务完成

#### WorkerGracefulShutdownHook

优雅下线钩子：
- 注册JVM ShutdownHook
- 注册SIGTERM/SIGINT信号处理器
- 监听Spring ContextClosedEvent
- 触发排空流程并等待任务完成

#### WorkerLifecycleManager

生命周期管理：
- 实现SmartLifecycle接口
- stop()时执行优雅下线
- 心跳上报DRAINING状态
- 下线完成后上报DOWN状态

#### WorkerDispatchController

任务派发控制：
- DRAINING状态拒绝新任务
- 返回`WORKER_DRAINING`错误码
- 任务执行完成后释放槽位

### 2. Scheduler端

#### WorkerHeartbeatApplicationService

心跳处理增强：
- 处理DRAINING状态心跳
- DRAINING状态活跃任务为0时转换为DOWN
- DOWN状态心跳转换为UP（Worker重启场景）

#### WorkerStateMonitorService

Worker状态监控：
- 定时扫描所有Worker状态
- 心跳超时检测（30秒）
- DRAINING超时检测（60秒）
- 自动回收不可用Worker的任务

#### JdbcWorkerRuntimeRepository

新增方法：
- `findAll()`: 查询所有Worker
- `deleteByWorkerId()`: 删除Worker记录

## 状态转换流程

```
UP ──(收到关闭信号)──> DRAINING ──(任务完成/超时)──> DOWN
 │                                                    │
 └──────────────(重启心跳)─────────────────────────────┘
```

## 优雅下线时序

```
1. 收到SIGTERM/SIGINT信号
2. WorkerGracefulShutdownHook触发
3. 设置draining=true，拒绝新任务
4. 上报DRAINING状态心跳
5. 等待活跃任务完成（最长30秒）
6. 任务完成后上报DOWN状态
7. 进程退出
```

## 配置示例

```yaml
ast:
  worker-sdk:
    graceful-shutdown-enabled: true
    graceful-shutdown-timeout-seconds: 30
    draining-poll-interval-ms: 1000
```

## 符合AGENTS.md约束

- Worker通过平台注册并上报心跳
- Worker周期性上报心跳包含状态信息
- 平台基于Redis运行态选点
- DRAINING状态Worker不参与调度
- 任务不会因Worker下线而丢失
