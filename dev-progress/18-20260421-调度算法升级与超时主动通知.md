# 开发进度记录 - 20260421

## 18. 调度算法升级与超时主动通知

### 1. 调度算法升级 (Least Loaded+)
- **逻辑增强**: 在 `JdbcWorkerRuntimeRepository` 中升级了选点 SQL。
- **排序维度**:
    1. `available_slots DESC`: 优先选择可用槽位最多的 Worker（负载最轻）。
    2. `error_rate ASC`: 在负载相同时，优先选择历史错误率最低的 Worker（质量优先）。
    3. `avg_rt ASC`: 优先选择平均响应时间最快的 Worker（性能优先）。
    4. `updated_at ASC`: 轮询兜底，确保相同负载下的 Worker 得到公平调度。
- **验证**: 通过 `LeastLoadedDispatchIntegrationTest` 验证了错误率维度的生效。

### 2. 超时主动通知实现
- **中枢增强**: `CompensatorApplicationService` 不再仅仅负责 Redis 层的任务回收，还增加了对 MySQL 事实表的扫描。
- **超时检测**: 
    - 引入 `executionTimeoutMs` 配置（默认 10 分钟）。
    - 扫描处于 `DISPATCHED` 或 `RUNNING` 状态且长时间未更新的任务。
- **主动通知流程**:
    - 发现超时任务后，原子化地将其状态流转为 `FAILED`。
    - 自动生成一条 `NotifyOutboxRecord`，通过回调机制通知业务方任务已超时失败。
    - 在 `compensation_audit` 中记录审计日志，方便回溯。
- **验证**: 新增 `SchedulerTimeoutNotifyIntegrationTest` 完整验证了“任务卡死 -> Compensator 扫描 -> 状态置灰 -> 触发通知”的全链路。
