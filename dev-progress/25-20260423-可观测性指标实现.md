# 25-20260423-可观测性指标实现

## 背景
根据 AGENTS.md 要求，必须有结构化日志、`traceId`、关键业务指标，至少覆盖：提交TPS、入队成功率、调度延迟、执行耗时、重试数、死信数、Redis队列积压、RocketMQ堆积、Worker心跳成功率、业务回调成功率。

## 实现内容

### 1. 依赖添加
- **task-gateway/pom.xml**：添加 `micrometer-registry-prometheus`
- **task-scheduler/pom.xml**：添加 `micrometer-registry-prometheus`

### 2. 指标常量定义
创建 `MetricNames` 常量类，定义所有业务指标名称：

| 指标名称 | 类型 | 说明 |
|----------|------|------|
| `ast_task_submit_total` | Counter | 任务提交总数 |
| `ast_task_submit_success` | Counter | 提交成功数 |
| `ast_task_submit_failure` | Counter | 提交失败数 |
| `ast_task_submit_duration` | Timer | 提交耗时 |
| `ast_task_cancel_total` | Counter | 任务取消总数 |
| `ast_task_cancel_success` | Counter | 取消成功数 |
| `ast_outbox_publish_total` | Counter | 外盒发布总数 |
| `ast_outbox_publish_success` | Counter | 外盒发布成功数 |
| `ast_outbox_publish_failure` | Counter | 外盒发布失败数 |
| `ast_outbox_republish_total` | Counter | 外盒重发总数 |
| `ast_task_dispatch_total` | Counter | 调度总数 |
| `ast_task_dispatch_success` | Counter | 调度成功数 |
| `ast_task_dispatch_failure` | Counter | 调度失败数 |
| `ast_task_dispatch_duration` | Timer | 调度耗时 |
| `ast_task_dispatch_delay` | Timer | 调度延迟 |
| `ast_task_callback_total` | Counter | 回调总数 |
| `ast_task_callback_success` | Counter | 回调成功数 |
| `ast_task_callback_failure` | Counter | 回调失败数 |
| `ast_task_retry_total` | Counter | 重试任务数 |
| `ast_task_dead_letter_total` | Counter | 死信任务数 |
| `ast_business_notify_total` | Counter | 业务通知总数 |
| `ast_business_notify_success` | Counter | 业务通知成功数 |
| `ast_business_notify_failure` | Counter | 业务通知失败数 |
| `ast_worker_heartbeat_total` | Counter | Worker心跳总数 |
| `ast_worker_heartbeat_success` | Counter | 心跳成功数 |
| `ast_worker_heartbeat_failure` | Counter | 心跳失败数 |
| `ast_worker_available_slots` | Gauge | Worker可用槽位 |
| `ast_redis_queue_ready_size` | Gauge | Redis Ready队列大小 |
| `ast_redis_queue_processing_size` | Gauge | Redis Processing队列大小 |
| `ast_redis_queue_retry_size` | Gauge | Redis Retry队列大小 |
| `ast_rocketmq_consumer_lag` | Gauge | RocketMQ消费延迟 |

### 3. 业务指标采集集成

#### task-gateway
- **TaskSubmissionApplicationService**：
  - 任务提交指标（总数、成功、失败、耗时）
  - 任务取消指标
  - 外盒发布指标
  - 外盒重发指标

#### task-scheduler
- **DispatcherApplicationService**：
  - 调度指标（总数、成功、失败、耗时、延迟）
- **WorkerCallbackApplicationService**：
  - 回调指标（总数、成功、失败）
  - 重试指标
  - 死信指标
- **NotifyApplicationService**：
  - 业务通知指标（总数、成功、失败）
- **WorkerHeartbeatApplicationService**：
  - 心跳指标（总数、成功）
  - Worker可用槽位 Gauge

### 4. 基础设施指标采集

#### RedisQueueMetricsCollector
- 定时采集 Redis 队列积压（每5秒）
- 暴露 `ast_redis_queue_ready_size`、`ast_redis_queue_processing_size`、`ast_redis_queue_retry_size`

#### RocketMqMetricsCollector
- 定时采集 RocketMQ 消费延迟（每10秒）
- 暴露 `ast_rocketmq_consumer_lag`

### 5. 标签设计

| 标签名 | 说明 |
|--------|------|
| `tenant_id` | 租户ID |
| `task_type` | 任务类型 |
| `worker_id` | Worker ID |
| `worker_group` | Worker组 |
| `status` | 状态 |
| `error_code` | 错误码 |

## 使用方式

### 访问 Prometheus 端点
```
GET http://localhost:8080/actuator/prometheus
GET http://localhost:8081/actuator/prometheus
```

### Prometheus 配置
```yaml
scrape_configs:
  - job_name: 'ast-platform'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['task-gateway:8080', 'task-scheduler:8081']
```

### Grafana 查询示例
```promql
# 任务提交 TPS
rate(ast_task_submit_total[1m])

# 提交成功率
rate(ast_task_submit_success[1m]) / rate(ast_task_submit_total[1m]) * 100

# 调度延迟 P99
histogram_quantile(0.99, rate(ast_task_dispatch_delay_bucket[1m]))

# Redis 队列积压
ast_redis_queue_ready_size
```
