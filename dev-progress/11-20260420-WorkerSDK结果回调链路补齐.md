# Worker SDK 结果回调链路补齐

## 本次进展

- 升级了 `WorkerSdkProperties`，支持配置 `workerId` 和 `workerGroup`。
- 升级了 `WorkerDispatchController`：
    - 在异步执行 `TaskExecutionHandler.handle` 后，自动根据执行结果调用 `WorkerControlPlaneClient.callbackResult` 上报状态。
    - 成功时上报 `TaskStatus.SUCCESS`。
    - 抛出异常时上报 `TaskStatus.FAILED`（目前默认 `retryable=true`）。
- 完善了 `TaskWorkerSdkAutoConfiguration`，支持自动注入回调所需的依赖。
- 更新了调度器集成测试 `HttpWorkerDispatchIntegrationTest`，补齐了 SDK 侧的配置项，验证了派发链路的完整性。

## 当前状态

- 任务执行闭环已打通：`Gateway -> MQ -> Pump -> Redis -> Dispatcher -> Worker SDK -> Scheduler Callback`。
- 业务方只需实现 `TaskExecutionHandler` 即可自动获得：
    1. 异步任务接收。
    2. 执行结果自动上报。
    3. 异常时的重试触发。

## 下一步建议

- **任务生命周期追踪**：目前 `traceId` 虽然定义了，但尚未在调度和回调链路中全量透传和记录日志。
- **Compensator 扫描**：针对调度器派发后宕机（任务卡在 `processingQueue`）的情况，实现自动扫描与回收。
- **可观测性监控**：在 `task-scheduler` 中引入 Prometheus 指标，监控各个队列的积压情况和派发成功率。
